# 005. AIGC 封面生成（推迟到 Phase 5 首版完成后单独评估）

**登记日期**:2026-06-10
**触发条件**:Phase 5 B-roll 闭环（ISS-028）落地试用一段时间后，若 demo 演示中"封面图静态截图首帧"的视觉占位被反复反馈不足，再启动本规划。

## 背景

PLAN.md 2119-2154 行 Phase 5 完整范围含三件事:贴纸生图 + B-roll 视频生成 + **封面生成**。decisions/013 把 Phase 5 跨级实施的范围收窄到 B-roll + 贴纸两件事，封面延后。

封面生成的工作量与 B-roll / 贴纸不在一个量级——它需要:

- LLM 从 ASR + 项目元数据抽取 3 个"封面文案候选"(独立 prompt 设计 + 多版本 UI)
- 用户从 3 个候选中选 1 个 + 提供风格偏好
- 生图 API 根据封面文案 + 模板风格 + 用户首帧生成 1080×1920 PNG
- Editor 端新增"生成封面"按钮 + 文案候选选择 UI + 多版本切换
- 封面元数据需要在 ProjectIR 顶层独立挂字段（非 Section 内,不入视频时间线）
- 产物披露:封面 PNG 元数据写 AI 生成标记 + 提示用户保存到独立目录

PLAN 2139 行的 Agent 工具协议已声明 `generate_cover(project_ir, ledger, style_hint) -> image_path` 签名，本规划落地时按该签名实现即可。

## 触发条件细化

满足以下任一即启动本规划:

- 用户在 demo 演示中明确反馈"分享视频到平台时缺统一封面，每次手动截图很麻烦"。
- 团队评估短视频平台（抖音 / 视频号 / 小红书）的发布流程时，发现封面是必须步骤而非可选项。
- ISS-028 / ISS-029（Phase 3 长视频）落地后，长视频项目的"封面建议"需求被显式提出。

## 实施依赖

- decisions/013 的 `agent/aigc.py` provider 抽象已落地（共享同一 hash 缓存模式 + 事件发射协议 + provider 配置接口）。
- ProjectIR 增 `cover_path: str | None` + `cover_metadata: dict | None` 顶层字段。
- Editor 端首屏布局允许加新按钮（项目右上角"生成封面"），不影响现有三栏布局。
- 5.aigc.cover stage 加入命名规范表（与 5.aigc.broll / 5.aigc.sticker 同前缀）。

## 不在本规划范围

- 多版本封面对比 UI（"高点击 / 高质感 / 高节奏"四档,PLAN 2270 行 Phase 7 任务 10 范畴）——延后到结构重排能力做完，封面多版本与重排多版本天然同框。
- 平台尺寸适配（横屏 16:9 / 方形 1:1）——首版只产出 1080×1920 单尺寸，PLAN 0 阶段 D6 编解码归一化已锁定输出比例。
