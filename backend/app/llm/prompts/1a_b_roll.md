# 画面构成识别（1A.b_roll）

你看到的是一段视频中某个 scene 的中间帧。请判断这一段画面的**构成类型**：

| 类型 | 含义 |
|------|------|
| `人物主导` | 画面以一个真人讲话为主，背景是物理拍摄场景。这是口播视频最常见的形态——若不确定就归这一类。 |
| `全屏 B-roll` | 画面整屏被换成图片 / 短视频片段 / AI 生图 / 空镜 / 数据图表，没有讲解人物。 |
| `画中画` | 主画面（讲解人）仍在，但叠加了一个小窗口（正方形 / 圆形）显示别的内容。 |
| `侧栏` | 画面被切成两块（左右或上下），一侧是讲解人 / 主体，另一侧是图表 / 信息卡 / 静帧 / 第二画面。 |

按以下 JSON Schema 严格输出。

## 输出 JSON Schema

```json
{
  "kind": "人物主导" | "全屏 B-roll" | "画中画" | "侧栏",
  "bbox_norm_0_999": [x_left, y_top, w, h] | null,
  "confidence": 0.0-1.0,
  "reasoning": "≤200 字中文解释"
}
```

## bbox 填写规则

- `kind=人物主导`：`bbox_norm_0_999=null`（整屏都是主体）。
- `kind=全屏 B-roll`：`bbox_norm_0_999=null`（整屏都是 B-roll）。
- `kind=画中画`：`bbox_norm_0_999` 填**小窗口的位置**（左上 + 宽高，0-999 归一化）。
- `kind=侧栏`：`bbox_norm_0_999` 填**非主讲人那一侧**的 bbox。

## 关键约束

- 只看画面构成，不看音频。
- 字幕 / UI 元素 / 标题条 / 水印 / 贴纸**不作为判定信号**——它们叠加在主画面上，不改变 kind。
- 主体微小晃动 / 镜头平移**不改变 kind**——一段画面如果整体都是讲解人在镜头前讲话，即使有运镜也归 `人物主导`。
- `confidence < 0.5` 时默认归 `人物主导`——口播视频里 B-roll / 画中画 / 侧栏占比远低于人物主导，宁可漏报也不要误报，避免下游 AIGC 子能力在不需要时被触发。
